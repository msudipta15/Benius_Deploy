BENIUS — TEACHER PASSWORD CHANGE BLOCKED BY ARCHIVED SESSION GUARD

MODE: STRICT READ-ONLY AUDIT

ISSUE:
Teacher Portal → First Login → Change Password

URL:
/teacher-login

When the Teacher enters and confirms a new password and clicks Update Password, BENIUS displays:

"Security Restriction: Write operations are strictly blocked for archived school years."

OBJECTIVE:
Find the exact cause and recommend the smallest secure correction.

AUDIT:

1. Identify the frontend API request used for mandatory Teacher password changes.

2. Identify the backend route, authentication middleware, password validation and update logic.

3. Check whether the frontend automatically attaches x-view-session-id to the password-update request.

4. Check whether the global archived Academic Session write guard intercepts this request.

5. Verify whether the Teacher password-change operation is account-level rather than Academic Session–specific.

6. Check whether a stale Academic Session selection can trigger the error.

7. Verify that any proposed exemption would apply ONLY to the exact Teacher password-change endpoint.

8. Confirm that the Teacher must still be authenticated through the correct pending-password-change or first-login flow.

9. Ensure that changing a Teacher password cannot modify academic records, school configuration or another school's accounts.

10. Check whether Principal and Student password-change flows have similar vulnerabilities, but do not modify them.

RECOMMENDED FIX TO EVALUATE:

If confirmed, prevent the exact account-level Teacher password-change request from being blocked by Academic Session restrictions.

Preserve:
- Teacher authentication.
- School/tenant isolation.
- Password security and hashing.
- First-login password-change enforcement.
- All archived-session restrictions on academic data.
